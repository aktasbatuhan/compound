The evidence

Same weights, six hosts: 0% to 55% task success.

We ran one open model (deepseek-v4-flash) on six pinned serving hosts through terminal-bench: 252 agentic episodes, pass or fail decided by each task's own test suite, every failed episode's raw API traffic audited.

  • Model quality is a statistical tie; the serving layer is not. Every functioning host lands at 45 to 57% once provider-killed episodes are excluded. End to end, the spread is 0 to 55%.
  • One host scored 0 of 42 with a perfectly healthy model. Its endpoint rejects the response format the agent needs on every turn. Invisible on single-turn benchmarks, fatal for agents.
  • Identical calls, 5x latency spread. And different determinism: one host flipped 2 of 14 task outcomes between identical trials, another 7 of 14.

The pipeline

One compound.yaml. One content-addressed cache.

Everything runs locally with no account: SQLite storage, your keys in .env, your traces never leave your machine. Each stage writes evidence the next one reads.

01 / INGEST

Bring your traces

Langfuse export or portable JSON. Redaction runs before anything is persisted. No eval authoring.

compound import export.jsonl
02 / CURATE

Traces to cases

Provenance-typed eval cases under a replayability contract, split into immutable train, validation, calibration, and sealed decision partitions.

compound curate support
03 / BACKTEST

Replay candidates

Any model x provider x quant replays against your graded corpus from the cache. Free assertions filter before judge tokens; re-deciding costs $0.

compound experiment support kimi-k3
04 / OPTIMIZE

Close the gap

The real GEPA library evolves a cheaper candidate's prompt on train and val cases, never the sealed set. "No improvement" is a first-class outcome.

compound optimize support --candidate M
05 / GATE

Ship on a verdict

The gate decides over cached runs on the sealed set with a rule declared before anyone looks, and emits one of five honest verdicts.

compound gate support --reason "…"
What's in the box

Built like an audit, not a dashboard toy.

Every number is reproducible, every comparison shows its fingerprint, and no run spends a cent you didn't authorize.

$

Money-safe by default

Without --paid, zero provider calls, just an estimate. Paid runs need an enabled budget, a hard USD limit, and a --cap. Every completion is cached, so a re-run costs $0.

⌗

Fingerprint caching

A content-addressed key over case, prompt, tool schema, sampling params, provider revision, and judge version: the difference between a $2 and a $200 run.

§

Sealed decision partition

Optimizers, prompt selection, and judge tuning never see the decision set. Opening it requires a stated --reason. That firewall keeps the verdict honest.

κ

Calibration-gated judges

A judge feeds a gate only after it out-agrees human labels (Cohen's kappa with a bootstrap CI) above threshold. Until then it abstains: an untrusted opinion never becomes a switch signal.

±

Intervals, never bare means

Paired-bootstrap confidence bounds on every comparison. The gate emits a non-inferiority decision, not a point estimate you have to eyeball.

⇄

Provider pinning, verified

One flag isolates a single serving host with fallbacks disabled, and the served host is recorded on every call, so a pinned run can be checked, not trusted. Works for third-party agent harnesses through a local proxy.

Declarative config

The whole loop is one file.

compound.yaml is the source of truth: task keys, judges, rubrics, gates, budgets.

compound.yamlv1
# the gate rule, declared before you look
gate:
  metric: task_success
  max_regression: 0.02
  require_decision_test: true

# a judge only counts once calibrated
judges:
  support:
    model: anthropic/claude-opus-4.8
    calibration_threshold: 0.6
    decision_point: 0.5

# free checks run before judge tokens
assertions:
  support:
    - { type: tool_called, name: dispute_charge }
    - { type: max_length, max: 1500 }

budget:
  paid_runs_enabled: true
  hard_limit_usd: 25.00
  • Declare the rule first. The gate's threshold is fixed and content-hashed before anyone looks at results. The sealed set cannot be reverse-fit to the answer you wanted.
  • Assertions before judges. Deterministic checks are free; judge tokens are not. Cheap filters run first, every time.
  • Budget is a hard wall. Paid runs are off until you enable them and set a positive USD limit, then bounded by a per-run --cap.
  • One discipline, two stacks. The TypeScript engine and the Python benchmark library share the same sealed-partition and budget-cap rules, so what you test behaves like what you ship.
